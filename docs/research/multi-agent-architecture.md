# Put code in charge, agents on judgement

> Research report, 30 September 2026. It reviews the design as it stood before the grilling session, which assumed Claude models; [decision 0002](../decisions/0002-open-weight-models-only.md) has since moved every agent to open-weight models, and the design docs in [`docs/design/`](../design/) supersede its recommendations where they differ. Source notes are in [`notes/multi-agent-architecture/`](notes/multi-agent-architecture/).

As of September 2026 the best multi-agent LLM systems share one shape. Deterministic code holds the plan and does all the maths. One orchestrator owns the final decision and is the only part that writes or acts. Specialists get their own clean context, read or review, and hand back short structured summaries. A separate evaluator with explicit criteria checks the work. Anthropic, OpenAI, Google, Microsoft, LangChain and Cognition, once the leading sceptic of multi-agent designs, now broadly agree on this. They also agree on the entry rule: start with one agent and add more only for context protection, parallel breadth or a security boundary. The FPL agent already gets the hardest parts right. The LLM never predicts points, a MILP optimiser sits behind MCP, memory is kept in files, and human approval guards irreversible chips. Its weak spots are the ones the 2026 evidence targets. Three interdependent mid-model analysts split one sequential decision along job titles. The sceptic is framed as a debater, not a criteria-driven evaluator. An LLM orchestrates a weekly sequence that is known in advance. And the plan to auto-submit real transfers combines untrusted news, account credentials and state-changing writes in one system, which also breaches the FPL terms. The highest-value changes are to move the fixed pipeline into Python, merge the analysts into one planner, turn the sceptic into a blind, rubric-graded checker, harden the news-to-execution path, and make prospective, timestamped live results the headline eval. The last section ranks these changes and notes which rest on weak sources.

## Six vendors converged on orchestrator, isolated readers and a single writer

Anthropic's December 2024 taxonomy is still the reference, and its advice has not reversed: "finding the simplest solution possible, and only increasing complexity when needed". Its patterns run from prompt chaining and routing up to orchestrator-workers and evaluator-optimizer ([Anthropic](https://www.anthropic.com/engineering/building-effective-agents)). What 2026 added is conditions and numbers. A January 2026 Claude blog post names **three cases where multi-agent wins: context protection, parallelisation and specialisation**. It puts the cost at **3 to 10 times the tokens of a single agent on the same task**, and it tells builders to **decompose by context boundary, not by problem type**. Splitting sequential phases across agents creates a "telephone game" in which "each handoff loses context" ([Claude blog](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them)).

The other vendors say the same thing in different words. OpenAI: "Start with one agent whenever you can", with specialists called as tools when "the main agent should stay responsible for the final answer" ([OpenAI](https://developers.openai.com/api/docs/guides/agents/orchestration)). Microsoft: "Use the lowest level of complexity that reliably meets your requirements", validate each agent's output before passing it on, and give each agent a model that matches its task ([Microsoft Learn](https://learn.microsoft.com/en-us/azure/architecture/ai-ml/guide/ai-agent-design-patterns)). Google Cloud: start with one agent, and consider non-agentic solutions for predictable workloads ([Google Cloud](https://docs.cloud.google.com/architecture/choose-design-pattern-agentic-ai-system)).

The public debate ended in a compromise, not a winner. In June 2025 Cognition argued "Don't Build Multi-Agents" because "actions carry implicit decisions" ([Cognition](https://cognition.com/blog/dont-build-multi-agents)). By April 2026 the same author wrote that multi-agent systems work "when **writes stay single-threaded** and the additional agents contribute intelligence rather than actions". He called unstructured swarms "mostly a distraction" ([Cognition](https://cognition.com/blog/multi-agents-working)). A second line of agreement concerns who holds the plan. OpenAI calls code orchestration "more deterministic and predictable" on speed, cost and performance ([OpenAI Agents SDK](https://openai.github.io/openai-agents-python/multi_agent/)). Claude Code's dynamic workflows "move the plan into code" so the model's context holds only the answer ([Claude Code docs](https://code.claude.com/docs/en/workflows)). The applied-LLMs authors recommend deterministic plans executed reproducibly ([applied-llms.org](https://applied-llms.org/)).

The frameworks have converged too, so the choice between them matters less. LangGraph 1.2, Microsoft Agent Framework 1.x (which replaces AutoGen, now in maintenance mode), Google ADK 2.x, CrewAI Flows and Pydantic AI all pair an agent loop with an explicit workflow layer, checkpointed state and human approval ([LangGraph](https://docs.langchain.com/oss/python/langgraph/overview), [AutoGen README](https://github.com/microsoft/autogen), [Pydantic AI](https://pydantic.dev/docs/ai/overview/)). "Harness" is now the standard name for this layer.

The Claude Agent SDK is a credible choice for this project, but it is pre-1.0 (0.2.162 on 29 September 2026). It runs the Claude Code binary as a subprocess ([PyPI](https://pypi.org/project/claude-agent-sdk/), [Agent SDK overview](https://code.claude.com/docs/en/agent-sdk/overview)). Its subagents start fresh, and "only its final message returns to the parent". Anything a subagent needs must go in the prompt string. Depth, concurrency and `max_budget_usd` caps exist because "Claude Opus 5 delegates to subagents more readily than earlier models" ([Subagents in the SDK](https://code.claude.com/docs/en/agent-sdk/subagents)).

## Debate loses, and sequential decisions degrade when split

The strongest measured evidence works against two parts of the current design. Google Research tested 180 agent configurations. Centralised coordination improved a parallelisable financial-reasoning task by about 81%, but **every multi-agent variant degraded sequential planning tasks by 39 to 70%**. Independent agents amplified errors 17.2 times, against 4.4 times with a central coordinator ([Google Research](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/)).

A gameweek decision is sequential and tightly coupled. Fixtures, transfers, chips and captaincy all draw on one budget and one squad. Three analysts split by job title are exactly the decomposition this finding and Anthropic's context-boundary rule warn against. The scout is different. Reading news across 20 clubs is read-only, parallel work, which is where gains are expected.

The MAST study annotated 1,600 traces from seven frameworks. It found that **failures came mainly from system design (43.8%) and inter-agent misalignment (32.3%)**, not from weak individual agents. Verification failures made up another 23.5%. The models in that study predate 2026 ([arXiv 2503.13657](https://arxiv.org/html/2503.13657v3)).

On critics, the literature separates two things that often share a name. Symmetric debate between similar agents rarely beats single-agent chain-of-thought or self-consistency, even with more compute. Model heterogeneity is the one reliable improvement ([arXiv 2502.08788](https://arxiv.org/abs/2502.08788)). A 2026 study measured debate at 2.1 to 3.4 times the tokens of self-correction for equal or lower accuracy, with agents conforming to the majority up to 85.5% of the time. That study used only 7-8B open models ([arXiv 2605.00914](https://arxiv.org/abs/2605.00914)). Competitive debate also degenerates into "debate hacking", where persuasion wins over truth. A collaborative variant that verifies quoted evidence and uses a calibrated judge did better ([arXiv 2510.20963](https://arxiv.org/html/2510.20963v2)).

An asymmetric evaluator is the pattern that consistently works. Anthropic found that "tuning a standalone evaluator to be skeptical turns out to be far more tractable than making a generator critical of its own work" ([Anthropic](https://www.anthropic.com/engineering/harness-design-long-running-apps)). Cognition's reviewer shares no context with the author on purpose, and catches about 2 bugs per PR, roughly 58% of them severe ([Cognition](https://cognition.com/blog/multi-agents-working)). The named failure mode is "early victory": a verifier runs one or two checks and declares success ([Claude blog](https://claude.com/blog/building-multi-agent-systems-when-and-how-to-use-them)).

The practical conclusion: **a sceptic that "argues against the move" should become a blind, criteria-driven checker**. It should run on a different model from the proposer. It should see the proposed move and the tool outputs, not the Manager's reasoning. And it should work through a mandatory checklist.

## Innovations worth borrowing come from small models escalating, graded outcomes and curated memory

Four 2026 patterns are relevant to this project.

**The advisor strategy.** This inverts the big-model-orchestrates-small shape. A cheap executor runs the task and consults Opus only at hard points. Anthropic reports Sonnet with an Opus advisor scored 2.7 points higher on SWE-bench Multilingual than Sonnet alone, at 11.9% lower cost per task ([Claude blog](https://claude.com/blog/the-advisor-strategy)). Cognition adds a limit: the pattern failed when the primary model was too weak to know when to escalate ([Cognition](https://cognition.com/blog/multi-agents-working)).

**Graded outcomes.** Managed Agents' "outcomes" feature pairs a rubric with a grader in its own context window. Anthropic claims up to 10 points of task success from it. Its "multiagent" feature gives each specialist its own model, prompt and tools on a shared filesystem ([Claude blog](https://claude.com/blog/new-in-claude-managed-agents)). Managed Agents now covers this project's exact shape: cron deployments, memory, budgets and multi-agent runs. It is still beta ([Managed Agents overview](https://platform.claude.com/docs/en/managed-agents/overview)).

**Curated memory, not rewritten memory.** ACE treats context as a playbook that a Generator, Reflector and Curator update with itemised changes, and so avoids "context collapse" from repeated rewriting ([arXiv 2510.04618](https://arxiv.org/abs/2510.04618)). A 2026 memory survey names the main danger as **self-reinforcing error**: a wrong lesson stops the agent from gathering the evidence that would overturn it. It recommends that every lesson cite specific evidence and carry an expiry ([arXiv 2603.07670](https://arxiv.org/html/2603.07670v1)). Plain files are a defensible memory store. Letta's filesystem agent scored 74.0% on LoCoMo, above Mem0's own reported graph score ([Letta](https://www.letta.com/blog/benchmarking-ai-agent-memory/)). But the memory benchmark rankings conflict depending on who ran them.

**Neuro-symbolic division of labour.** The LLM ranks or sets parameters, and a fixed numeric engine computes. Direct LLM forecasting failed badly on "incorrect scale or unit assumptions" ([arXiv 2607.24892](https://arxiv.org/html/2607.24892v1)). In LLM-written optimisation models, **54.8% of failures were modelling errors**, and the best agent passed only 35.51% of tasks ([arXiv 2606.19787](https://arxiv.org/html/2606.19787)). Both results support keeping the MILP hand-written and letting agents pass only validated parameters.

Among reference repositories, **TradingAgents** (109k stars) is the closest structural analogue. It uses parallel analysts, a bull/bear debate capped at a set number of rounds, "deep think" and "quick think" model tiers, structured outputs, and a decision log. Each later run reads that log with the realised returns and turns them into lessons ([TradingAgents](https://github.com/TauricResearch/TradingAgents)). Its backtest claims deserve scepticism. An August 2026 honest-evaluation study found every LLM-discovered trading strategy failed certification, and a deliberately leaked oracle still passed statistical deflation ([arXiv 2608.27734](https://arxiv.org/html/2608.27734)).

Within FPL itself, **fpl-copilot** commits its recommendations to git before each deadline so the timestamps prove nothing was retrofitted. It grades against three naive baselines and lets the LLM write the memo but never the numbers ([fpl-copilot](https://github.com/subhasishgoswami02/fpl-copilot)). **lewis-king/fpl-mcp-server** keeps FPL credentials out of the model with an out-of-band login ([repo](https://github.com/lewis-king/fpl-mcp-server)). **fantasypl/mcp** uses golden-file tests on frozen API payloads and hold-out-season backtests ([repo](https://github.com/fantasypl/mcp)). One LangGraph FPL manager with seven agents and a PuLP solver already exists as a portfolio piece ([repo](https://github.com/EliDehaene01/Fantasy-Premier-League-Manager)). A Claude Agent SDK harness with a solver-backed MCP server, deferred approval and prospective evaluation is still an open niche. All of these FPL repos have tiny star counts and were judged only from their READMEs.

On protocol, MCP's 2026-07-28 spec makes the core stateless and deprecates Sampling, Roots, Logging and HTTP+SSE ([MCP blog](https://blog.modelcontextprotocol.io/posts/2026-07-28/)). For a local server the spec recommends stdio ([MCP security](https://modelcontextprotocol.io/specification/2026-07-28/basic/security_best_practices)). Anthropic's tool guidance favours a few task-level tools that return high-signal fields, names instead of raw ids, and error messages that tell the agent how to fix the call ([Anthropic](https://www.anthropic.com/engineering/writing-tools-for-agents)). A2A 1.0 is for agents talking across organisations, not for subagents inside one process ([A2A](https://a2a-protocol.org/latest/specification/)).

## Tracing standards are still unstable, and live forward testing is the only clean eval

The OpenTelemetry GenAI agent conventions (`invoke_agent`, `invoke_workflow`, `gen_ai.usage.*`) are **still "Development" status**. They sit in a new repository with no tagged release ([semconv-genai](https://github.com/open-telemetry/semantic-conventions-genai/releases)), so "OTel GenAI-compliant" should be claimed with that caveat.

The Agent SDK exports OTLP natively. Its traces are beta, and the span names are Claude-specific (`claude_code.llm_request`, `claude_code.tool`). Subagent spans nest under the parent's tool span. `TRACEPARENT` makes the run a child of the application's own span. There are pitfalls for a short weekly job: export errors are silent, the default export interval is 5 seconds, and spans can be dropped on exit ([Agent SDK observability](https://code.claude.com/docs/en/agent-sdk/observability)). Langfuse's documented route is the OpenInference instrumentor with `langfuse.flush()`. That page says nothing about token, cost or subagent capture ([Langfuse](https://langfuse.com/integrations/frameworks/claude-agent-sdk)).

Cost accounting has one trap. Result `usage` excludes subagents, while `total_cost_usd` and `model_usage` include them. `total_cost_usd` is a client-side estimate, not billing truth ([Agent SDK cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking)).

Current Anthropic prices per million tokens (input/output) are Opus 5.5 $4/$20, Sonnet 5.5 $2/$10 and Haiku 4.5 $1/$5. **Haiku needs at least 4,096 tokens before it will cache a prompt**, so short Haiku scout prompts will silently not cache ([pricing](https://platform.claude.com/docs/en/about-claude/pricing), [caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). A weekly run gets no caching benefit across runs. Caching only pays within one run, which needs a stable prefix of tools and system prompt, with gameweek data last. The Batch API's 50% discount fits offline grading jobs, not the agent loop ([batch](https://platform.claude.com/docs/en/build-with-claude/batch-processing)).

On evals, Anthropic recommends **20 to 50 tasks drawn from real failures**. Grade the outcome, not the path. Report pass^k as well as pass@k, and calibrate LLM judges against human labels ([Anthropic](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)). Paired differences with **clustered standard errors** matter because clustering can make the error "over three times as large" ([Anthropic](https://www.anthropic.com/research/statistical-approach-to-model-evals)). Hamel Husain and Shreya Shankar put error analysis on real traces first. They recommend binary judgements, one validated judge per failure mode, and looking for the first upstream failure in a trace ([hamel.dev](https://hamel.dev/blog/posts/evals-faq/)).

Temporal leakage is worse than the project's note admits. HindsightBench finds effective model cutoffs **up to 8 months earlier than vendors state**, with period knowledge leaking into every 2026 model tested ([arXiv 2607.18867](https://arxiv.org/abs/2607.18867)). Masking entity names only partly helps ([arXiv 2511.15364](https://arxiv.org/html/2511.15364v2)). The clean design is prospective, as in ForecastBench ([arXiv 2409.19839](https://arxiv.org/abs/2409.19839)) and LLM-SoccerArena. The latter found that web access improved World Cup Brier scores by only **0.023** ([arXiv 2607.24573](https://arxiv.org/abs/2607.24573)). That is a sobering prior for how much a news scout will add. The Brier score is the right metric for any probabilities the agents emit. Verbalised confidence often does not track accuracy ([arXiv 2607.20526](https://arxiv.org/abs/2607.20526)).

## The control layer has a hazard: the agent combines all three risky capabilities

Meta's "Rule of Two" says an agent should hold no more than two of these at once: untrusted input, sensitive access, and state change. If it needs all three, it needs supervision ([Meta AI](https://ai.meta.com/blog/practical-ai-agent-security/)). Simon Willison's "lethal trifecta" makes the same point for data exfiltration ([Willison](https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/)).

The FPL agent reads scraped news, holds a refresh token, and submits transfers, so it holds all three. The principled fixes are the dual-LLM and CaMeL designs: a quarantined model handles untrusted text without tools, and policy is enforced at each tool call ([arXiv 2503.18813](https://arxiv.org/abs/2503.18813)). For this project that means the scout emits only a constrained schema, the Manager never sees raw web text, and a deterministic policy check runs before any write.

The SDK supports approvals that wait for a slow human. A `PreToolUse` hook can return `defer`, the process exits, and it resumes later from the persisted session. A `PermissionRequest` hook can send a notification. `AskUserQuestion` does not work inside subagents, so approval gates must live in the Manager or in hooks ([Handle approvals](https://code.claude.com/docs/en/agent-sdk/user-input)).

Separately, the project's own feasibility research found that the FPL terms forbid "automated systems to access the Game" (clause 28(d)), with suspension as the penalty ([feasibility note](../docs/research/fpl-api-feasibility.md)). Auto-execution on the owner's account is therefore a deliberate terms risk, not just an engineering choice. Confirm mode, where the owner clicks confirm in the FPL app, should remain the default.

## Recommendations, ranked by the owner's priorities

The table orders changes by expected effect on performance first, then cost, then observability and evals. Each row names its evidence and how strong that evidence is.

| # | Change | Evidence | Evidence strength |
|---|---|---|---|
| 1 | **Move the weekly pipeline into Python.** Fixed stages: snapshot, xP, scout, plan, check, optimise, validate, approve, execute, journal. Each stage is idempotent and keyed by gameweek. Agents are called inside those stages instead of the Manager deciding the sequence turn by turn. | OpenAI code orchestration; Claude Code workflows; applied-llms; Google sequential degradation | Strong (multiple vendors plus one large study) |
| 2 | **Merge the fixtures, transfers and chips analysts into one planner agent that shares context.** Keep the parallel Haiku scout. Test the merge by ablation: one planner against three analysts. | Context-boundary rule; 39-70% sequential degradation; MAST misalignment share | Moderate: no study on weekly decision agents, and the heuristics carry no thresholds |
| 3 | **Rebuild the sceptic as a blind evaluator.** Run it on a different model from the proposer, with a fixed checklist: evidence quoted from tool outputs, injury status checked, hit cost, fixture horizon, chip timing. Give it an explicit "insufficient evidence" verdict. It sees the move and the data, not the Manager's rationale. Cap it at one round. | Anthropic sceptical evaluator; Cognition clean-context reviewer; debate literature; heterogeneity finding | Moderate: vendor results are internal, and the debate papers use older or small models |
| 4 | **Harden the path from news to execution.** The scout gets no credentials and no write tools, and returns only `{player, status enum, probability, source_url}`. A deterministic policy check runs before any write (legal squad, budget, hit cap, deadline, the payload matches the approved plan). Execution is dry-run by default, carries a per-gameweek idempotency key, and re-reads account state afterwards. Deferred approval runs through a `PreToolUse` hook with a notification. | Rule of Two; CaMeL; SDK approvals docs; CLAUDE.md write rules | Strong on principle; the "not adopted by mainstream harnesses" claim is unverified |
| 5 | **Make prospective live results the headline eval.** Commit each decision with a timestamp to git before the deadline. Report paired per-gameweek differences between solver-only and solver-plus-agents, with clustered standard errors and a statement that power is low over 38 gameweeks. Label every past-season agent backtest as contaminated. Keep backtests for the solver and the plumbing. | ForecastBench; SoccerArena; HindsightBench; Anthropic stats post; fpl-copilot | Strong for design; the leakage papers are 2026 preprints |
| 6 | **Grade the agents' pieces, not just points.** Hand-label scout extractions and score precision and recall. Have agents emit probabilities (starts, ruled out, captain beats the alternative) and Brier-score them after the gameweek. Build a 20-50-case regression suite from real failures, with binary judges validated for TPR and TNR. | Anthropic evals post; Hamel/Shankar FAQ; ConfidenceBench | Strong (convergent practitioner guidance) |
| 7 | **Turn the journal into an ACE-style playbook.** Lessons are itemised, each cites its gameweek and evidence, each is a process lesson rather than an outcome lesson, and each has an expiry. The harness injects the relevant lessons at decision time. Scraped text never enters memory unreviewed. | ACE; memory survey; AI Village; Letta | Moderate: ACE results are author-reported and memory benchmarks conflict |
| 8 | **Put hard limits on cost.** Set `max_budget_usd`, a spawn depth of 1 and low concurrency. Keep tools and system prompt stable at the front of the prompt, with no timestamps there. Check `cache_read_input_tokens` for each subagent, since Haiku needs 4,096 tokens to cache. Tools return top-N compact results with player names. Use the Batch API for offline grading. Measure cost per point from `model_usage`, reconciled against the Usage API. | SDK cost docs; caching docs; tool-writing post | Strong (primary docs); savings figures are Anthropic's own |
| 9 | **Make tracing reliable.** Create an application root span per run, with `session.id` set to the gameweek and prompt and agent versions in `service.version`. Lower the export intervals, enable `CLAUDE_CODE_OTEL_DIAG_STDERR`, and call `flush()`. Compare the native export against OpenInference on one run and keep whichever records per-subagent cost. Pin versions, since the conventions are in Development. | SDK observability docs; semconv status; Langfuse docs | Strong on mechanics; Langfuse's handling of `claude_code.*` spans is unverified |
| 10 | **Try the advisor pattern as a cost ablation.** A Sonnet planner consults Opus only for chip and wildcard weeks, compared with Opus as Manager. Adopt it only if points per pound improve. | Advisor post; Cognition's escalation caveat | Weak: one vendor's benchmarks on coding and browsing tasks |
| 11 | **Recruiter-facing polish.** Write ADRs in `docs/decisions/` for items 1-4. Use a stdio MCP server built on `mcp` 2.x or FastMCP 4.x, with no deprecated features. Optionally publish it to the MCP Registry (still in preview). Name Managed Agents as the hosted path. Mention durable execution only as an option: DBOS is the lightest, and no engine integrates with the Claude Agent SDK. | MCP spec; registry page; durable-execution notes | Moderate; "overkill" for weekly jobs is an inference |

Several findings rest on weaker ground and should not be over-quoted:

- The advisor figures, the Managed Agents outcome gains and the 90.2% multi-agent research result are vendor-internal evaluations.
- The debate-negative papers mostly test QA and maths with older or small models. Nothing tests FPL-like decisions under uncertainty.
- The memory benchmark numbers conflict by author.
- CaMeL's adoption status, the MCP tool-poisoning statistics and GEPA's production claims came from search snippets.
- No study covers low-frequency, weekly batch agents, and no published FPL agent has out-of-sample results. The fit to this project is inferred.
- The FPL ban-enforcement claim has no primary source.

## Conclusion

The field's centre of gravity has moved from designing an agent team to designing a harness around a small number of agents. The interesting engineering now sits in state, verification, context boundaries and evaluation, not in how many roles exist. For this project, the stronger resume story is not "six agents cooperate". It is that the project measured which agents earn their tokens and deleted the ones that did not. The ablation the owner already planned is the right instrument. Pointed at the architecture itself (one planner against three analysts, blind sceptic against debating sceptic, scout on against scout off), it turns the agent graph into a set of tested hypotheses.

The second shift is that honesty about evaluation has become a technical differentiator. Leakage research now shows past-season agent backtests are close to meaningless. Timestamped live decisions graded against a solver-only baseline are the result a sceptical reviewer will trust. And in a domain where web access moved World Cup forecasts by only 0.023 Brier, "the agents add little over the solver" is a plausible and publishable outcome.
